## ۰. نقش، مأموریت و خواسته‌های صریح کاربر

شما مهندس ارشد فول‌استک ادامه‌دهندهٔ پروژهٔ **NIR** هستید (سامانه مدیریت جامع کارخانه خوراک طیور: حواله‌های ورود/خروج، باسکول، مرغداران و دوره‌های پرورشی، انبار/سیلو، رانندگان و گزارش‌ها). این پروژه شامل سه بخش یکپارچه در همین مخزن است:

1. **سرور (Backend):** Node.js / Express 5 + Drizzle ORM + PostgreSQL (`server.ts` و `server/**`).
2. **وب (Web Frontend):** React 18 + Vite + Tailwind (RTL) در ریشه مخزن (`pages/`, `components/`, `index.tsx`).
3. **موبایل (Mobile App):** Expo SDK 51 / React Native 0.74.5 در پوشه `nir-mobile/` (نقش‌های `MANAGER`, `DRIVER`, `FARMER`, `OPERATOR`) و نسخه وب مستقر روی `https://dev.artadan.ir/mobile`.

### خواسته‌های مؤکد و صریح کارفرما:
1. **استفاده از تمام اطلاعات واقعی سایت دو (`dev.artadan.ir` / دیتابیس `nir_dev`):**
   * کاربر صراحتاً خواسته است: *«شامل تمام اطلاعات سایت دو باشه، نمی‌خوام تستی یا ساختگی باشه»*.
   * کلیه اطلاعات نمایش داده شده در اپلیکیشن (مرغداران، تمامی دوره‌های پرورشی ثبت‌شده در دیتابیس، بارنامه‌ها و قبوض باسکول، تناژهای واقعی) باید **مستقیماً از جداول واقعی دیتابیس `nir_dev`** واکشی و محاسبه شوند.
   * **ممنوعیت مطلق داده‌های فیک/ماک:** هیچ داده هاردکد، هیچ دوره ساختگی یا مقادیر تستی نباید در صفحات نمایش داده شود.
   * هر مرغداری که شماره تلفنش در دیتابیس ثبت است باید بتواند وارد شود و تمام دوره‌های واقعی خود را ببیند. مدیر نیز در پنل خود بتواند هر یک از مرغداران واقعی را انتخاب و کارنامه و دوره‌های او را بررسی کند.
2. **وضعیت پنل پیامکی (تعریف در آینده):**
   * کاربر اعلام کرده است: *«بعداً پنل پیامکی رو تعریف می‌کنیم روش»*.
   * در حال حاضر روی سرور توسعه، فلگ `MOBILE_OTP_DEBUG=true` فعال است و برای هر شماره ورودی، کد تأیید برمی‌گردد تا کار توسعه و تست مسدود نشود.
   * ساختار کد در `server/services/smsService.ts` از قبل آماده اتصال به کلید وب‌سرویس پیامک (مانند Kavenegar / FarazSMS) است؛ پس از تحویل نهایی تنها با قرار دادن API Key در `.env` پیامک واقعی فعال خواهد شد.
3. **طراحی فوق‌العاده زیبا، مدرن و امکانات کامل دوره‌های پرورش:**
   * کاربر صراحتاً اعلام کرده است: *«اطلاعات هیچ کدوم از دوره های پرورش درست نیست و نمایش داده نمی شه و اصلا ظاهر خوبی نداره و امکانات هم نداره خیلی خیلی ابتدایی هست»*.
   * ظاهر صفحات باید کاملاً مدرن، شکیل، با پالت رنگی حرفه‌ای، کارت‌های آماری های‌تک، نوارهای پیشرفت چندرنگ و فونت چشم‌نواز وزیرمتن باشد و امکانات کاملی برای دوره‌های پرورش ارائه دهد.

## ۳. ریشه‌یابی باگ دوره‌های پرورش و راهکار جامع

### ۳-۱. علت نمایش داده نشدن اطلاعات دوره:
در فایل `nir-mobile/src/screens/farmer/FarmerDashboardScreen.tsx` خط ۳۳:
```tsx
const activePeriod = data?.activePeriod || data?.brood;
```
در حالی که بک‌اند در `GET /api/mobile/farmer/dashboard` کلید را به نام **`activeBrood`** برمی‌گرداند (`data.activeBrood`). به همین دلیل `activePeriod` مقدار `undefined` گرفته و سن گله ("نامشخص") و تعداد جوجه ("—") خالی نشان داده می‌شوند. همچنین بک‌اند در حال حاضر تنها یک دوره را ارسال می‌کند و آرایه کامل تمام دوره‌های مرغدار (`farmer.broods`) را برنمی‌گرداند.

### ۳-۲. الزامات کامل برای پیاده‌سازی ماژول دوره‌های پرورش:

1. **ارتقای بک‌اند در `server/routes/mobile.ts`:**
   * **ارسال تمامی دوره‌های واقعی مرغدار:** فیلد `broods: Brood[]` شامل تمام دوره‌های ثبت‌شده در ستون `farmers.broods` (فعال، خاتمه‌یافته، بایگانی‌شده) مرتب بر اساس تاریخ شروع.
   * **ارسال همزمان کلیدهای استاندارد:** بازگرداندن `activeBrood` و `activePeriod` به همراه اطلاعات کامل: نام دوره، تاریخ شروع جوجه‌ریزی، تعداد قطعه، سن گله، درصد پیشرفت سن، تلفات و تناژ مصرفی.
   * **پذیرش پارامتر دوره:** در اندپوینت `GET /api/mobile/farmer/statement?broodId=...`، صورتحساب و لیست بارنامه‌ها دقیقاً بر اساس دوره انتخاب‌شده (بازه زمانی تاریخ شروع و پایان آن دوره) فیلتر و محاسبه شود.
   * **اندپوینت افزودن دوره:** `POST /api/mobile/farmer/broods` برای تعریف دوره جدید توسط مرغدار یا مدیر با تاریخ شروع شمسی و تعداد قطعه.
   * **اندپوینت خاتمه دوره:** امکان ثبت تاریخ پایان و وزن نهایی مرغ برای بستن دوره.

2. **طراحی رابط کاربری (UI/UX) بسیار زیبا، مدرن و شکیل در موبایل/وب:**
   * **انتخابگر دوره (Period Selector):** چیپ‌های افقی یا منوی بازشونده جذاب برای جابجایی سریع بین دوره فعال و دوره‌های قبلی مرغدار.
   * **ویجت گرافیکی سن گله و روزشمار:** نمایش روز پرورش با نوار پیشرفت تمیز از روز ۱ تا ۵۰.
   * **کارت‌های آماری لوکس (Metrics Grid):**
     * تعداد قطعه جوجه اولیه
     * تلفات ثبت‌شده و درصد زنده‌مانی گله
     * میانگین مصرف روزانه دان (گرم به ازای هر قطعه)
     * ضریب تبدیل غذایی تخمینی (FCR)
   * **ویجت فازهای خوراک طیور (Feed Stages):**
     * پیش‌دان (Starter - روز ۱ تا ۱۰)
     * میان‌دان (Grower - روز ۱۱ تا ۲۸)
     * پس‌دان (Finisher - روز ۲۹ به بعد)
     با نمایش سهمیه هر فاز، مقدار تحویل شده و درصد پیشرفت.
   * **لیست بارنامه‌های متصل به دوره:** جدول یا کارت‌های شکیل برای بارنامه‌های خروجی کارخانه با نمایش شماره بارنامه، نوع دان، وزن باسکول، وزن بارنامه و وضعیت انطباق.
   * **مودال‌های کاربردی:** فرم ثبت دوره جدید (`NewBroodModal`) و فرم بایگانی دوره.

## ۴. دستورهای حیاتی، تست، بیلد و استقرار

تمامی مراحل بیلد و استقرار باید به ترتیب زیر و فقط روی محیط dev انجام شوند:

```powershell
# ۱. تست‌های سرور و کلاینت
npm test
npm run test:mobile
npm run test:mobile-client
npm --prefix nir-mobile run typecheck

# ۲. بیلد وب اپلیکیشن موبایل (Expo Web)
$env:APP_VARIANT='dev'; $env:EXPO_PUBLIC_API_URL='https://dev.artadan.ir'; npx --prefix nir-mobile expo export --platform web --output-dir dist-web

# ۳. کپی فایل‌های وب موبایل به dist-dev و بیلد dev سرور
if (Test-Path "dist-dev\mobile") { Remove-Item -Path "dist-dev\mobile" -Recurse -Force }; Copy-Item -Path "nir-mobile\dist-web" -Destination "dist-dev\mobile" -Recurse -Force
npm run build:dev

# ۴. استقرار روی سرور dev (با اعتبارسنجی خودکار عدم تغییر prod)
powershell -ExecutionPolicy Bypass -File .\psremoting\wb-dev-deploy.ps1

# ۵. تست سلامت و ایزولاسیون کامل ۲۶ شاخص
powershell -ExecutionPolicy Bypass -File .\psremoting\verify-dev-isolation.ps1
```
